## חלק א': למה דווקא הסטאק הזה?

הבחירה שלי מוכתבת משלוש דרישות שלך: **חינם**, **אתה לא מתכנת**, ו**חייב להיות מוכן להפוך לאפליקציה בעתיד**.

| שכבה | הבחירה | למה זה |
|---|---|---|
| **קוד (מקור האמת)** | **GitHub** | סביבת העבודה שלי בענן היא זמנית — היא נמחקת. GitHub הוא הזיכרון הקבוע של הפרויקט. בלעדיו כל ריצה מתחילה מאפס. |
| **אחסון האתר** | **Vercel** (תוכנית Hobby) | מתחבר ל-GitHub פעם אחת. מרגע זה — כל שינוי שהסוכנים דוחפים עולה לאוויר לבד תוך ~60 שניות. אתה לא נוגע בכלום. |
| **דאטהבייס + משתמשים** | **Supabase** (Free) | Postgres אמיתי + מערכת הרשמה/התחברות מוכנה + **API אוטומטי**. ה-API האוטומטי הוא בדיוק ה-"API-First" שביקשת — אותו שרת בדיוק ישרת בעתיד את האפליקציה ב-iOS. |
| **טכנולוגיית הצד הקדמי** | **Next.js + React + TypeScript + Tailwind** | React הוא התנאי שלך למעבר עתידי ל-React Native. TypeScript מונע כ-40% מהבאגים שסוכני AI נוטים לייצר. |
| **מובייל** | **PWA מיום ראשון** | ניתן לשמור למסך הבית של הטלפון כבר בשבוע הראשון, בלי חנות אפליקציות ובלי 99$ לאפל. |

**מה שקלתי ופסלתי:**

* **Firebase** — נדיב בחינם, אבל האחסון של Next.js מלא דורש שדרוג בתשלום, ומבנה הנתונים שלו (NoSQL) גרוע במיוחד למה שאתה בונה: אלגוריתם ריווח חזרות דורש שאילתות מורכבות ("כל המילים שמועד החזרה שלהן היום, ממוינות לפי קושי") — זה מגרש הביתי של Postgres, לא של Firestore.
* **Lovable / Bolt / בוני-אתרים בעזרת AI** — מרשימים בהתחלה, אבל הם מייצרים קוד סגור שקשה לתחזק, אין להם לופ ביקורת אמיתי, והם עולים כסף מהר. ומעל הכל: אתה מבקש מערכת שתתפתח לאורך חודשים — לזה צריך ריפו אמיתי.
* **Cloudflare Pages + D1** — אלטרנטיבה חינמית מצוינת, ואם Vercel יגביל אותנו בעתיד נעבור לשם. בשלב זה Vercel פשוט יותר להתקנה.

**עלות בפועל:** 0 ₪ עד לסביבות 1,000 משתמשים פעילים בחודש. אחר כך כ-$25/חודש.

## חלק ב': 7 הצעדים שאתה מבצע (רק לחיצות, בלי קוד)

> אין צורך להתקין שום דבר על המחשב. הכל דרך הדפדפן.

### צעד 1 — חשבון GitHub  *(5 דק')*
1. היכנס ל-<https://github.com/signup> ופתח חשבון עם `roygindi2@gmail.com`.
2. אשר את המייל.
3. לחץ על ה-**+** בפינה הימנית העליונה ← **New repository**.
4. מלא כך:
   * **Repository name:** `english-loop`
   * **Private** ← בחר בזה (הפרויקט שלך, לא ציבורי)
   * סמן ✅ **Add a README file**
5. **Create repository**.

### צעד 2 — מפתח גישה ל-GitHub (PAT)  *(5 דק')*
זה מה שיאפשר לסוכנים שלי לכתוב קוד לריפו שלך.

1. גש ל-<https://github.com/settings/personal-access-tokens/new>
2. **Token name:** `cowork-agent-loop`
3. **Expiration:** 90 days
4. **Repository access:** בחר **Only select repositories** ← ובחר רק את `english-loop`
5. **Permissions** ← **Repository permissions** ← מצא את **Contents** והעבר ל-**Read and write**. (וגם **Pull requests** ← Read and write, אם מופיע.)
6. **Generate token** ← **העתק את המחרוזת שמתחילה ב-`github_pat_`**.

> 🔐 **על אבטחה, בכנות:** המפתח הזה נותן גישת כתיבה **רק לריפו הזה ולשום דבר אחר**, והוא פג תוקף אוטומטית תוך 90 יום. כדי שהתזמונים האוטומטיים יעבדו בלי שתהיה נוכח, המפתח יישמר בתוך הגדרות המשימה המתוזמנת בחשבון שלך. זה פשרה מודעת ולגיטימית בהיקף הזה. אם משהו משתבש — כפתור **Revoke** באותו עמוד מבטל אותו מיידית.

### צעד 3 — Supabase (הדאטהבייס)  *(8 דק')*
1. <https://supabase.com/dashboard> ← **Sign in with GitHub**.
2. **New project**:
   * **Name:** `english-loop`
   * **Database Password:** לחץ Generate ו**שמור אותה** במקום בטוח
   * **Region:** `Frankfurt (eu-central-1)` — הכי קרוב לישראל, המהיר ביותר
3. המתן ~2 דקות עד שהפרויקט קם.
4. גש ל-**Project Settings** ← **API** והעתק לפנקס שלושה דברים:
   * `Project URL`
   * `anon public` key
   * ~~`service_role` key~~ ← **לא נדרש.** אין קובץ שקורא אותו (T-024/F-010), ולכן אין להעתיק אותו לשום מקום. אם בכל זאת ראית אותו על המסך — הוא סוד, ואין לשתף אותו.

### צעד 4 — Vercel (העלאה לאוויר)  *(5 דק')*
1. <https://vercel.com/signup> ← **Continue with GitHub**.
2. בחר את התוכנית **Hobby** (חינם).
3. **Add New** ← **Project** ← אשר ל-Vercel גישה ל-`english-loop` ← **Import**.
4. הוא ייכשל בבנייה הראשונה כי הריפו ריק — **זה תקין וצפוי**. פשוט עזוב את המסך.

### צעד 5 — הזנת המפתחות ל-Vercel  *(4 דק')*
בתוך הפרויקט ב-Vercel: **Settings** ← **Environment Variables**. הוסף שלושה, אחד-אחד:

| Name | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ה-Project URL מצעד 3 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ה-anon key מצעד 3 |
| `SUPABASE_SERVICE_ROLE_KEY` | ה-service_role key מצעד 3 |

## נספח ב': שני צעדים שחייבים לקרות ב-Supabase לפני ההרשמה האמיתית הראשונה (T-002)

### ב-1 — הרצת המיגרציה של טבלת `profiles`
1. Supabase Dashboard ← **SQL Editor** ← **New query**.
2. הדבק את כל תוכן הקובץ `supabase/migrations/0001_profiles.sql` מהריפו ← **Run**.
3. ודא בלשונית **Table Editor** שהטבלה `profiles` קיימת ושמופיע לידה תג **RLS enabled**.

> **למה זה קריטי:** מפתח ה-`anon` יושב בדפדפן של כל משתמש. טבלה בלי RLS
> בשכבה החינמית של Supabase היא **טבלה ציבורית** — כל משתמש יכול לקרוא את
> השורות של כולם. המיגרציה מפעילה RLS ומגבילה כל מדיניות ל-`auth.uid() = id`.
> הבדיקה `lib/supabase/rls.test.ts` שומרת על נוסח המיגרציה, אך **אינה יכולה
> לדעת אם הרצת אותה בפרויקט שלך.** הצעד הזה ידני ואין לו תחליף.

### ב-2 — הגדרת אימות אימייל
Supabase Dashboard ← **Authentication** ← **Sign In / Providers** ← **Email**:

| ההגדרה | מה קורה בפועל | מה המוצר עושה |
|---|---|---|
| **Confirm email = ON** | ההרשמה לא מחזירה session. נשלח מייל אישור. | מסך ההרשמה מציג "שלחנו לך מייל לאישור הכתובת" ומפנה להתחברות. |
| **Confirm email = OFF** | ההרשמה מחזירה session מיד. לא נשלח מייל. | הלומד עובר ישירות ל-`/onboarding`. |

הקוד תומך בשתי ההגדרות ואינו מניח אף אחת מהן. **ההכרעה איזו מהן נכונה למוצר
היא החלטת PM ולא החלטת Dev** — ראה את השאלה הפתוחה בסעיף 6 של `plan/60-findings.md`.
